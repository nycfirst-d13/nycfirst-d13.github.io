Laser Maker — Save to Cloud

Laser Maker is the browser-based vector design tool students use to create parts for the laser cutter. This guide covers its Google Drive integration — a feature that lets students export their designs directly to a shared class folder, with no student accounts or sign-in required.

Browser-only · no install Google Drive output No student logins Shared PIN auth
End-to-End
From Laser Maker to the cutter

A student's design goes from Laser Maker in the browser, through Google Drive, into Adobe Illustrator, through the Epilog print driver, and onto the Epilog Fusion Edge 36 — Students can easily save and teachers can easily manage.

Process
From design to Drive
  • 1
    Open Laser Maker on a Mac desktop in Chrome
    No install, no student accounts. Open Chrome and share the URL — works best on Mac desktops.
  • 2
    Students design their parts
    Process colors are locked per cut type — blue = main cut, red = fold, green = final cut, black = etch. No color mistakes travel to the laser.
  • 3
    Export → enter Design Name + Project
    Top bar export icon. The names become the Drive filename — keep them descriptive.
    name + project → name-project_laser.svg
  • 4
    Click "Save to Cloud" → enter class PIN
    First time: announce the PIN. Students type it once — it caches per device for the session, so they won't be prompted again.
  • 5
    Open Drive → Laser Maker Exports
    All student designs land in a subfolder for today's date. Files are named, dimensioned in real inches, and ready for Illustrator and the laser.

Setup — one time only
Backend Configuration

Laser Maker's cloud saving is powered by a Google Apps Script that runs under an associated STEM Center Google account. Complete this setup once — students never interact with any of it.

01
Create the Drive folder
In Google Drive, create a folder called "Laser Maker Exports". Open it and copy the folder ID from the URL — it's the string after /folders/.
02
Create an Apps Script project
Go to script.google.com, create a new project, and paste the contents of docs/apps-script-uploader.js from this repo.
03
Set Script Properties
Project Settings → Script Properties. Add two keys — the PIN is never in source code.
DRIVE_PIN = stemcenter2026 ROOT_FOLDER_ID = <folder id>
04
Deploy as Web App
Deploy → New deployment → Web App. Execute as: Me. Who has access: Anyone. Authorize and copy the deployed URL.
05
Paste URL into the app
In modules/drive-upload.js, set DRIVE_UPLOAD_URL to the deployed URL. Done — commit and push.
Access Control
PIN Management in Laser Maker
Rotating the PIN
Change only the DRIVE_PIN Script Property. No redeploy needed. All cached PINs on student devices are rejected on their next export and they'll be prompted for the new one.
Where the PIN Lives
Never in app source code. Server side: Script Properties only. Client side: browser localStorage per device, auto-invalidated when the PIN rotates.
Wrong PIN
Dialog input shakes, shows an inline error, and clears the cached copy. No lockout — student just re-enters the correct PIN and the upload retries automatically.
Network Failure
If Drive is unreachable, the SVG downloads locally as a fallback. Students never lose work — the local file is always the safety net.
Implementation
How Laser Maker's "Save to Cloud" Works
User action
Click "Save to Cloud"
Export dialog validates Design Name and Project fields. SVG string is generated from the current canvas state via _makeSVG() in export.js.
App — drive-upload.js
Check PIN Cache
localStorage is checked for a previously validated PIN under key laserMakerDrivePin.
Cached PIN found → skip to POST No PIN → show dialog
UI
PIN Dialog
Modal prompts for the shared class PIN. Teacher announces it; students type it. Enter confirms, Escape skips and aborts the upload without error.
Skip → restore export dialog, no error
Network
POST to Apps Script
Fetch POST to the deployed Web App URL. JSON payload carries the PIN, the full SVG string, and the slugified filename.
Server — Google Apps Script
Validate PIN
Apps Script reads DRIVE_PIN from Script Properties and compares. The PIN is never in client source code — it lives only server-side.
Invalid → { error: "Invalid PIN" } → dialog shakes, retry
Server — Google Drive
Find or Create Today's Folder
Inside "Laser Maker Exports", Apps Script finds or creates a subfolder named with today's date (US Eastern). Keeps class sessions organized without any manual filing.
Server — Google Drive
Save SVG File
SVG written to the date folder as plain text. Duplicate filenames are kept — re-exports don't overwrite earlier versions, they stack alongside.
Returns { ok: true }
App
Cache PIN + Confirm
Validated PIN cached in localStorage. Subsequent exports skip the dialog. Green toast confirms: Saved to Drive · filename.
